### 3. 鉴权系统重写

**改前**：两道门 —— `ESSAY_AUTH` 环境变量（站点）+ `_SETTINGS_PW_DEFAULT = "wjlwjl2012"`（设置，
**硬编码在源码里**）。后者是开源绝对不能带的东西。

**改后**：单一口令，PBKDF2-SHA256（39 万轮 + 16 字节盐），格式 `sha256:<salt_hex>.<dk_hex>`
存 `data/config.json`。两个来源：

1. 环境变量 `ESSAY_PASSWORD`（明文，优先级高，方便容器部署）
2. `config.json` 的 `password_hash`（`setup.sh` 首次运行时写入）

**安全细节**：
- `_verify_password()` 格式坏 → 返回 False（**fail-closed**，绝不因读不出而放行）
- 比较走 `hmac.compare_digest`
- `_ENV_HASH_CACHE` 缓存 env 口令的哈希 —— `_password_hash()` 在**每个请求**上都被
  `_auth_required()` 调用，不缓存的话每次要跑 39 万轮 PBKDF2（约 100ms），整站会慢到没法用
- 设置页新增「🔒 访问口令」卡，可在网页内改口令 / 留空取消（后端 `new_password` 字段）

`app.js` 1597 → 1380 行；模板改用**未混淆**的 `app.js`（`?v=20261018a`）。

### 5. 新增 `setup.sh` 一键脚本

bash，四步：查 Python（≥3.8）→ 建 `.venv` → 装 Flask → **首次运行交互式设口令** → 启动。

关键设计：
- `cd "$(dirname "$(readlink -f "$0")")"` —— 双击运行时 cwd 不一定在项目里
- `[ -t 0 ]` 检测是否为真终端：**不是就跳过设口令并明确警告**（避免 cron/CI 里卡死等输入）
- 口令输两遍校验，**通过环境变量 `PW=...` 传给 Python，不进命令行**（`ps` 看不到）
- config.json 走**原子写**（临时文件 + `os.replace`）
- 默认绑 `127.0.0.1`；`HOST=0.0.0.0 sh setup.sh` 才对外，并给出警告
- 依赖装失败时给出**国内镜像源**和 `python3-flask` 系统包两条备选路

## 二、发现的问题（全部已定位，多数是**我自己的测试写错**，非产品 bug）

### 已确认为测试错误（产品行为正确）

| 现象 | 真因 | 修法 |
|---|---|---|
| `test_setup_pty.py` 报「明文口令落盘」 | 断言拿 `"88"` 判泄露 —— salt/dk 是十六进制，出现 `88` 纯属巧合 | 改成只断言完整明文串 |
| 批改流返回 202「还没配置 AI 接口」 | 没 API key 时后端走「待批改」队列模式，**根本不调 AI** | 测试先塞一把假 key |
| 流式响应读不到内容 | 生成器是**惰性**的，`get_data()` 不触发 | 改用 `iter_encoded()` 读完 |
| 断言 `"event:done"` 不匹配 | SSE 实际格式是 `event: done`（**冒号后有空格**） | 改成 `"event: done"` |
| 改口令断言全红 | `ESSAY_PASSWORD` 环境变量优先级**高于** config（设计如此），测试里 env 一直生效 | 测改口令前先 `pop` env + 清 `_ENV_HASH_CACHE` |
| UI 报「零 JS 报错」失败 | 未登录时 `loadList()` 必然 401 —— **那正是登录遮罩该出现的信号** | 剔除预期的 401 |
| UI 卡在 `#appView` | 我猜错容器 id，实际是 `<main id="app">` / `#view-list` | 改选择器 |

### 已确认为真实问题（本次发现并修掉）

1. **`_SETTINGS_PW_DEFAULT = "wjlwjl2012"` 硬编码在源码里** —— 这是自用版为了「两台机器零配置」
   做的妥协，开源版绝不能带。已改为 `config.json` 存哈希 + `setup.sh` 首次询问。

2. **`app.js:40` 注释仍写 `ESSAY_AUTH`**（环境变量名已改）—— 属于「常量/名字改了但注释没跟上」
   这一类，会让后来的维护者找错地方。已改。

### 已确认的产品行为（不是 bug，但值得记下来）

- **`highlights` 必须是对象数组** `[{"quote": "...", "issue": "..."}]`，不是字符串数组。
  后端 `_anchor_annotations()`（`app.py:242`）取 `h.get("quote")`，给字符串直接抛
  `AttributeError: 'str' object has no attribute 'get'`。**报错信息里没说字段名**，第一次
  定位花了点时间（靠 monkeypatch `_err_msg` 打印 `traceback` 才抓到）。
  → 建议后续给 `require_result()` 加一条「字段类型校验」，把这类错在解析阶段就拦下并
  明确说是哪个字段。

- **`_local_scoring` 会按字数重算扣分**：桩 AI 报 46 分，落盘是 **43 分**（不足 500 字扣 3）。
  正确行为，但**测试断言不能把 AI 报的数字写死**，要读落盘值。

## 四、没修的项与理由

1. **`api.deepseek.com` 保留在 `DEFAULT_CONFIG` 里** —— 那是**默认服务商地址**（不含任何 Key），
   给开源用户的合理默认值，删掉反而不好用。同理保留了设置页里小米 MiMo / DeepSeek / 通义千问
   三个**预设**（只有 base_url + 模型名，无凭据）。

2. **未加「字段类型校验」到 `require_result()`** —— 见上文 `highlights` 那条。这是**改自用版**
   也会受益的增强，但属于新功能，需用户点头；本次只做剥离。

3. **`doc_text.py`（旧版 .doc 解析）保留** —— 虽然小众，但用户上传老 Word 文件时有用，
   且是零依赖纯标准库实现（约 300 行）。

4. **`/api/analyze`（AI 学情分析）保留** —— 它是「多篇作文一起分析」，属于批改的自然延伸，
   与数据同步/控制面板那类基础设施不同。若用户认为开源版「只做作文批改」应连它一起砍，
   说一声即可（删一个路由 + 前端一个视图，成本很低）。
