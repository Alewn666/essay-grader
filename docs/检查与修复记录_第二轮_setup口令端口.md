# 检查与修复记录 —— 第二轮：setup.sh 管口令与端口，无口令锁站

日期：2026-10-18　范围：开源版 `essay-grader/`（NAS 归档同步 `作文批改（开源）/`）

## 用户需求（原话大意）

1. setup.sh 里可以**修改密码**，且是**第一次设置密码的地方**；
2. **没设密码就访问网页 → 弹出「请去终端设置密码」**（不再允许裸奔）；
3. setup.sh 里可以**自定义端口**。

## 结论

三条全部实现并验证通过。

## 改动明细

### app.py
- **无口令 = 整站锁定**（原语义是「没口令谁都能进」，已废除）：
  - 新增 `_setup_needed()`；`_require_auth()` 对锁定态返回 **403 `no_password`**（API），
    页面照常渲染（`needs_setup` 遮罩接管）；
  - `/api/login` 锁定态也 403（不再有任何登录入口）；
  - `_check_password()` 锁定态返回 False（堵死「空口令直接通过」）。
- **网页改口令不允许留空**：`/api/config` 的 `new_password` 空串 → **400**
  （留空 = 把自己锁在门外，只能去终端 setup.sh 重设）。
- **端口记住**：`DEFAULT_CONFIG` 加 `"port": 8083`；`__main__` 优先级
  `PORT 环境变量 > config.json 的 port > 8083`（env 临时换端口不用改配置）。

### setup.sh
- 第 3 节重写：**首次设口令**（原逻辑保留）+ **二次运行可改口令**
  （提示「直接回车保持不变」，输入新口令则输两遍覆盖）；
- **交互选端口**：`端口 [回车 = 上次的/8083]`，选过写进 config.json；
- 顶部不再 `PORT="${PORT:-8083}"` 无脑盖值（会盖掉 config 记住的端口）——
  改为 env PORT > config port > 8083 在末尾统一解析；
- 非交互式（管道）不问口令，但**明确警告网站将锁定**（原文案「网页将完全开放」已废除）。

### 前端
- `index.html`：新增 `setupOverlay` 遮罩（纯提示，**没有输入框**），
  与登录遮罩互斥（`needs_setup` / `needs_auth` 二选一渲染）；
- `app.js`：`onLoginPage()` 把 `setupOverlay` 也算登录页（防 403 reload 死循环，
  与第三十二轮 #3 同款坑）；改口令空输入前端直接拦；版本戳 `?v=20261018b`；
- 设置页口令卡文案：「留空 = 取消口令」→「不能为空」+ 提示可在终端改。

## 没修的项 / 不修的理由

- **`ESSAY_PASSWORD` 环境变量仍可开站**（容器部署场景），这是设计而非漏洞；
  该路径不经过 setup.sh，属部署方显式选择。
- setup.sh 改口令失败（两次不一致）只警告不退出 —— 保持「不改就不动」语义，
  没有做强制循环重输（首设路径仍是循环直到一致）。
- 未动自用版 `essay-revise/`（它有自己的口令体系 ESSAY_SETTINGS_PW）。

## ⚠️ 通用教训

- **改「默认放行 → 默认锁定」类语义时，测试断言要跟着反转**，否则假红；
  且要同时检查**前端有没有依赖旧语义的文案/分支**（本次：口令卡「留空=取消」、
  非交互式「网页将完全开放」两处旧文案都是跟着语义反转一起删的）。
- 脚本顶部的 `PORT="${PORT:-8083}"` 这类「顺手给默认值」会在后面引入
  config 记忆功能时变成**静默盖值** —— 默认值应该放在最终解析处，不要提前塞。
